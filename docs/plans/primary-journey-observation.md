# Primary CV journey: five-user observation script

One-page facilitator guide · proposed 2026-10-24 · run after PR C.

**Purpose:** Can a first-time participant produce a reviewed CV in under 45 minutes, with no navigation coaching? This is a usability session, not a release sign-off.

## Prepare and introduce (before timing)

Use a fresh `/next/` workspace on the participant's phone. Record build/commit, device/browser, interface language and participant code P1–P5 (no name). Provide the fictional Yara PDF and one fixed fictional logistics advert; use the same materials across sessions. Say: “We are testing the tool, not you. Please say what you expect and where you are unsure. You can stop at any time.” Ask permission for written observations. Do not record the screen or collect personal CVs, keys or transcripts by default.

Use the copy-paste route. Let participants use a free chat they already have, with fictional data only. If access is unavailable, supply a prepared reply when needed and record **supplied reply**; do not describe that session as validating real-chat access. No payment or new account is required for the session.

## Task prompt and timing

Start the timer when the fresh preview opens. Say: **“Use this fictional CV and advert to prepare an application. Check the facts and any AI wording, then download a CV you would be comfortable sharing. Please try both HTML and Word.”** Give the goal, not button names or a click sequence.

| Observe these milestones without directing them | Note |
| --- | --- |
| Find import and inspect extracted source | Time; unnecessary retyping; confusion between source and profile. |
| Populate/check profile facts | Accepted/edited/rejected suggestions; duplicate education/language entry; whether they notice unsupported wording. |
| Add one advert | Wrong navigation; accidental extra advert; discovery of optional requirement/evidence review. |
| Create and tailor draft | Whether they understand copy/share/paste back; provider-choice detours; AI waiting time; unwanted overwrites. |
| Review and first export | Exact elapsed time; whether they read claims before ticking; format chosen; hints received. |
| Download and locate second format | Time; file access problems; whether each file opens on the phone. |

If stuck, first ask “What are you trying to do?” If they request help or make no progress for two minutes, offer the smallest hint and record its wording/time; do not count completion as unassisted. Stop timing at first reviewed download, then record second-format time separately. At 45 minutes record target missed; ask whether they wish to continue, with a 60-minute session cap. Record abandonment and the last successful step.

## Debrief (after timed task)

Ask: “What changed when you accepted a suggestion? What did the review checkbox mean? Did the app verify your claims?” Then ask them to find the advert's evidence check, AI prompt studio and 90-day plan without naming their navigation locations. Ask what felt unnecessary or missing and which step they least trusted. Do not teach the expected answers before recording theirs.

## Record and decide

Keep one row per participant: first-export minutes; both-format minutes; real chat/supplied reply; AI wait; hints; abandonments/errors; comprehension; optional-tool discovery; one anonymised observation. Keep notes privately with the maintainer; exclude personal content from repository reports. Report all five outcomes and the median, plus repeated sticking points.

Proposed pilot criterion: at least **4 of 5** first reviewed exports in **under 45 minutes**, without navigation hints. Report both-format success separately. Any data loss, unaccepted AI change, review bypass or unintended disclosure blocks rollout. Review comprehension failures and repeat affected tasks after changes. Without a comparable pre-change cohort, claim target attainment only—not a measured improvement. These observations do not tick the real-device release checklist automatically.
